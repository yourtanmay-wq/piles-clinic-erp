## 🟢 সমাধান — "বদলেছে কি না জিজ্ঞেস করো, পুরোটা আবার নামিও না"

**নতুন ফাইল:** `native/CloudListRevalidate.kt`

বড় তালিকা নামানোর **আগে** দুটো ছোট প্রশ্ন — দুটোর উত্তরই কয়েকশো বাইট,
একটাও সারি নামে না:

1. **কতগুলো সারি আছে?** — `HEAD` + `Prefer: count=exact`. উত্তর শুধু
   `Content-Range` হেডারে, **body একদম ফাঁকা**।
   (এই পথ অ্যাপে আগে থেকেই ছিল — `SupabaseClient.fetchCount`, ২০২৬-০৭-২৩।)
2. **সবচেয়ে নতুন `updatedAt` কোনটা?** — `limit=1`, একটাই ঘর। **এক সারি।**
   (নতুন `SupabaseClient.fetchMaxUpdatedAtOrNull`।)

দুটো মিলিয়ে টেবিলের একটা **"সই"**। গতবারের সইয়ের সঙ্গে হুবহু মিললে ⇒ একটা
সারিও বদলায়নি ⇒ **গতবারের উত্তরটাই দেওয়া হয়, এক ফোঁটাও নতুন ডেটা নামে না**।
সই না মিললে ⇒ **আগের মতোই পুরো তালিকা নামে**।

### কেন সই নির্ভরযোগ্য (কোডে মিলিয়ে দেখা, আন্দাজ নয়)
- **নতুন সারি** ⇒ সংখ্যা বাড়ে ⇒ ধরা পড়ে।
- **মুছে ফেলা** ⇒ সংখ্যা কমে ⇒ ধরা পড়ে। (এই অ্যাপে ডিলিট সত্যিকারের `DELETE`
  — `SupabaseClient.deleteById` — তাই সংখ্যা নিশ্চিত বদলায়।)
- **বদল** ⇒ `updatedAt` এগোয় ⇒ ধরা পড়ে। প্রতিটা লেখায় অ্যাপ নিজে `updatedAt`
  বসায় (কোডে **৮৫ জায়গায়** `isoNow()`), আর V223-এর ডেটাবেস-trigger ওই ঘরটাই
  পাহারা দেয়।

### ⛔ ছয়টা নিরাপত্তা-জাল
| অবস্থা | কী হয় |
|---|---|
| ছোট উত্তর (< ৩২ KB) | **কখনো জমা হয় না** — এক রোগী · এক দিন · এক id ধরে পড়ার আচরণ এক অক্ষরও বদলায়নি |
| কোনো URL প্রথমবার পড়া | **হুবহু আগের মতোই** — সই আনার খরচও হয় না |
| সই আনতে ব্যর্থ / সংখ্যা `-1` / `updatedAt` ঘর নেই | **পুরো তালিকা নামে** (আগের আচরণ) |
| পড়া ব্যর্থ (`null`) | **কিছুই জমা হয় না** ⇒ খাতার সারি **B446** ("নেট আটকালে ₹0") ফিরতে পারে না |
| নিজে কিছু সেভ করলে | **সব ভুলে যাওয়া হয়** — ঠিক সেই ৭টা জায়গায় যেখানে আগে থেকেই `CloudReadDedupe.clear()` ছিল |
| জমানো উত্তরের বয়স ১০ মিনিট পার | **নিঃশর্তে বাতিল**, সই মিললেও |

**⛔ B446-এর শিক্ষা আবার মানা হয়েছে:** "একবার ব্যর্থ হলে আর কোনোদিন চেষ্টা
কোরো না" — এই ধরনের শর্টকাট **রাখা হয়নি**। সই না পাওয়া গেলে সেবারের মতো পুরো
তালিকা নামে, পরের বার আবার চেষ্টা হয়।

## ⚠️ যেটা সৎভাবে জানানো দরকার — ১০ মিনিটের সীমাটা কেন

সইয়ের `updatedAt` অ্যাপ নিজে বসায়, **ফোনের ঘড়ি থেকে**। ডেটাবেসের V223 পাহারা
(`_rk_guard_no_older_overwrite`) নিশ্চিত করে কোনো সারির নতুন লেখা তার **নিজের**
আগের সময়ের চেয়ে পুরনো হতে পারে না। কিন্তু কোনো ফোনের ঘড়ি **পিছিয়ে** থাকলে
তার লেখা সময়টা টেবিলের **সবচেয়ে নতুন** সময়ের নিচে পড়তে পারে — আর তখন (যদি ঠিক
ওই সময়ে টেবিলে আর কোনো যোগ/মোছাও না হয়) সই বদলাবে না।

**এই সরু ফাঁকটার জন্যই ১০ মিনিটের সীমা।** সবচেয়ে খারাপ অবস্থাতেও পার্থক্য
১০ মিনিটের বেশি টিকতে পারে না, আর সেটা শুধু ওই এক অবস্থাতেই। নিজের ফোনে কিছু
সেভ করলে সঙ্গে সঙ্গেই সব ভুলে যাওয়া হয়, তাই নিজের কাজ কখনো পুরনো দেখায় না।

**⛔ যা ইচ্ছে করে করিনি:** ওয়েবের `WLV1_DELTA_OVERLAP_MS` (২৪ ঘণ্টা পিছিয়ে পড়া)
ছোঁয়াই হয়নি। ওটাই ভুল-ঘড়ির লেখা ধরার জাল — ওটা ছোট করলে বা এড়িয়ে গেলে তথ্য
হারানোর আসল ঝুঁকি ছিল। ওয়েবে তাই শুধু নিচের ছবি-বাদ দেওয়ার কাজটা করা হয়েছে।

## ✅ যাচাই — এবার সত্যিই চালিয়ে দেখা হয়েছে

আগের প্রতিটা সেশনে লেখা থাকত *"এখানে Kotlin কম্পাইলার নেই"*। **এবার আনা
হয়েছে** (kotlinc 2.0.21), আর আসল okhttp/org.json দিয়ে কোড সত্যিই কম্পাইল ও
**চালানো** হয়েছে।

### ১. কম্পাইল — **০ error**
বদলানো `SupabaseClient.kt` + নতুন `CloudListRevalidate.kt` + আসল
`CloudReadDedupe.kt` + `JsonExt.kt`, আসল okhttp 4.12 ও org.json দিয়ে।

### ২. আচরণ-পরীক্ষা — **১৪টির ১৪টিই পাশ**
```
PASS  1st read: downloads, spends 0 probe requests
PASS  2nd read: downloads once, probes once
PASS  unchanged table: downloads NOTHING
PASS  row added (count 10→11): downloads again
PASS  row edited (updatedAt moved): downloads again
PASS  row deleted (count 10→9): downloads again
PASS  probe failed (-1): downloads, never serves stale
PASS  no updatedAt column: downloads as before
PASS  small read: always goes to the network (unchanged)
PASS  failed read returns null
PASS  failed read was not stored: next read really downloads
PASS  cached body is byte-identical to the downloaded one
PASS  primed cache serves without download
PASS  clear() after a save forces a real download
```

### ৩. আসল কোড, নকল Supabase সার্ভার, **মেপে দেখা বাইট** — ১২টির ১২টিই পাশ
৩২৭৩ সারির নকল টেবিল, `branch=eq.KGJ` ⇒ ১৬৩৭ সারি, একবার পড়লে **২৭৩ KB**।
ডাকা হয়েছে আসল `SupabaseClient.fetchListSlimOrNull(...)` দিয়ে, ঠিক যেভাবে
বোর্ডের পর্দা ডাকে।

| পরীক্ষা | ফল |
|---|---|
| পর্দা খোলা #১ | ১৬৩৭ সারি · ২৭৩ KB |
| পর্দা খোলা #৩ (কিছু বদলায়নি) | **০ বাইট · ০ অনুরোধ** ✅ |
| কেউ একটা সারি **এডিট** করল | **আবার পুরো ২৭৩ KB নামল**, নতুন মানও পর্দায় ✅ |

| কেউ একটা সারি **মুছল** | আবার পুরো নামল · সারিটা সত্যিই নেই ✅ |

পরপর দুবার চালিয়েও একই ফল — একবারের কাকতালীয় নয়।
